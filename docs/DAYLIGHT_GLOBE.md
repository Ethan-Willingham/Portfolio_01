# Earth Now

The globe combines dated NOAA, JMA and EUMETSAT satellite observations, calculated sunlight, historical city lights and NOAA's short-term aurora forecasts. Each source keeps its own clock. The time controls select actual dated images and saved forecast grids where available. The site remains static, with locally vendored Three.js r128 and no new runtime library. The opening view centres on the device location with browser permission; its controls remain visible. The rolling time slider is the only time selection control.

## Satellite clouds and their history

Processing revision 16 replaces NASA GIBS display-palette inversion with original measurements from NOAA's public satellite archive. `tools/globe-numeric-clouds.py` reads GOES-18/19 ABI Level 2 CMI band 13 temperatures from NetCDF and Himawari-9 AHI band 13 counts from all ten HSD segments. Satpy calibrates the HSD counts using the file's calibration coefficients and navigation. EUMETView supplies the two monotonic greyscale Meteosat IODC IR108 and MTG IR105 products. No visible-colour image, inferred cloud-shape repair or ambiguous colour palette enters the rolling replay.

The reported October 9 Gulf artifact was a cold storm core decoded as warm background. NASA's display palette repeats greys at unrelated temperatures; the previous connected-region workaround could not recover the lost distinction. Native GOES measurements at 28.0371 N, 87.6270 W produce thermal value 240/255 where the old pipeline produced 0. The retained native NetCDF crop includes packed counts, DQF flags, original axes, projection and acquisition times. The regression checks those measurements rather than painting over a hole.

GOES accepts DQF 0, excludes fill and nonfinite values, and resamples temperatures in their native geostationary projection. Himawari's reader masks error counts and space. Bilinear interpolation requires valid neighboring samples, so missing data cannot become a bright stripe. Celsius temperatures map monotonically to the existing display field as `(30 - temperature) / 110`, clamped to 0 through 1. EUMETView pixels retain their monotonic greyscale contrast and native alpha. A three-degree inward coverage feather and satellite viewing-angle weights blend observed overlap. No clouds are extended into unobserved polar areas. Brightness illustrates temperature, not measured cloud fraction or optical depth; warm clouds can be faint and cold ground can resemble clouds.

Every satellite is selected independently, using the latest completed scan at or before the snapshot, at most 90 minutes old. GOES uses the actual acquisition start/end embedded in the NetCDF, checked against its object name. Himawari requires all ten segments and a completed ten-minute acquisition interval. Meteosat's nominal ten- or fifteen-minute scan must also finish before the selected time. An unavailable scan can fall back to an earlier real scan with its original clock. A failed region stays missing when no recent observation is available; it cannot freeze all the other satellites. At least three feeds and 30 percent measured global coverage are required for publication. The UI shows the actual range of observation ages, individual source times inside Sources & accuracy, and an explicit regional-gap note when a feed is missing.

The recorder polls every two minutes and stores ten-minute snapshots for 26 hours, at most 157 frames. It publishes the newest completed global frame before backfilling history, with bounded work per pass. The GitHub workflow explicitly queues its successor after each bounded run; the fifteen-minute cron is a recovery path because actual cron deliveries were separated by hours. Workflow concurrency permits one active writer. Manual cancellation stops the handoff. Provider or GitHub outages can still delay updates; the UI retains the actual ages. The browser checks the manifest every minute and never replaces a newer snapshot with an older metadata replica. Checks are keyed by UTC minute so download duration cannot make the timer skip alternate checks. GitHub's raw-file cache can still delay delivery of a published snapshot.

Version 3 manifests record each satellite's identity, product, source URL, acquisition start and acquisition end. The catalog lists only prepared ten-minute snapshots. Ten source slots and the paired image format remain for compatibility: five null visible slots, `natural: false`, a transparent companion, and a thermal field. Both images are lossless WebP. Frame clocks, provenance, bounded ages, dimensions, file sizes and SHA-256 hashes are validated. Processing revision 16 excludes every older palette-decoded frame, including from browser caches. A failed archive fetch can retain compatible installed data; the rolling view never silently substitutes display-colour or daily imagery.

`tools/archive-globe-clouds.cjs` publishes to the generated `globe-clouds` branch using a parentless bounded snapshot and an exact old-SHA lease. The cloud field supplies both day clouds and attenuation of city lights. Clouds, terrain and city lights use the same selected-time daylight curve. ## Aurora, replay and visibility

OVATION provides 65,160 geographic values: a one-degree grid with 360 longitudes and 181 latitudes, plus Observation Time and Forecast Time. The parser validates every cell, uniqueness, finite coordinates, probability range and valid UTC times. Pin sampling is bilinear with longitude wrapping. The GPU texture has two padded seam columns and ClampToEdge, so its 362 by 181 non-power-of-two dimensions work in WebGL1 as well as WebGL2. Geographic node centres, both polar rows and the duplicate seam are independently tested against raw source coordinates.

The glow follows every positive forecast probability with a continuous, proportional display mapping. Zero-probability cells remain dark. The original values remain available in the pin; the display texture quantizes each value to one byte without applying an extra probability threshold. No geographic latitude cutoff is imposed. `js/globe-aurora.js` creates thin, folded ribbons with genuine vertical geometry. Their rays follow an approximate centered dipole, while each geographic footpoint samples the untouched NOAA probability texture. Both hemispheres remain supported, including unusual low-latitude forecasts. Earth hides curtains behind it; their upper rays can rise beyond the limb, and orbiting changes their apparent depth. Green emission sits lower, with restrained red higher up and a faint violet lower edge. Fine rays use screen derivatives to avoid flickering at a distance. Slow changes in height and brightness suggest motion without moving the forecast oval.

The displayed base is about 100 km above Earth. The upper extent is deliberately stretched to roughly 900 km so the curtains read at globe scale. NOAA does not supply these individual heights, folds, rays, colours or calibrated radiance. Strength 1.5 sets illustrative screen exposure; daylight suppression, forecast timestamps, probabilities and locations retain their previous meaning. The fixed geometry uses eight WebGL1-compatible parts and about 13.2 MiB of typed buffers. Replay reuses those buffers and selects only forecast-supported segments, rather than rebuilding the ribbons on each time input. A real 28 percent saved forecast and the authentic 41 percent storm fixture both produce raised green pixels beyond the globe silhouette in Chrome and mobile WebKit. The old surface-shell alternatives have been superseded by these curtains.

Physical references: [NASA's description of curtains and field-aligned rays](https://pwg.gsfc.nasa.gov/Education/waurora1.html), [aurora photographed from the ISS](https://science.nasa.gov/earth/earth-observatory/aurora-australis-observed-from-the-international-space-station-44348/).

Stale glow disappears and is labeled unavailable. Kp retains its own three-hour interval and is not used to manufacture the oval. Earth keeps its actual date-specific tilt.

NOAA's public geographic JSON provides the latest forecast only. Its rolling image animation is not a historic numeric grid API. `tools/archive-globe-aurora.cjs` therefore preserves genuine fetched grids as compact, lossless, gzip JSON, retaining 30 days. The manifest records both source timestamps and SHA-256 of each saved file. Initial history contains authentic snapshots collected during development, beginning with observations on October 4, 2026 at 23:38 UTC; coverage initially has gaps.

`tools/archive-globe-weather.cjs` coordinates independent cloud-index and aurora captures. A narrowly scoped GitHub Actions workflow starts at minutes 7, 22, 37 and 52, then takes twelve fresh samples at five-minute intervals during each run. Keeping the runner active fills more history than depending on a new scheduled job for each sample. It retains up to 10,000 manifest entries, enough for 30 days of five-minute sampling. It validates freshness, avoids duplicate writes and commits only the aurora subtree and two cloud time indices, with bounded rebase retries. Actual schedule delivery can be delayed. Browser history reads raw files on the repository's main branch, independent of Pages rebuilds; GitHub's five-minute cache can add latency. The static deployed files provide a fallback copy. Each saved frame is about 4 to 6 KB compressed in sampled conditions. Retention deletes current files, while old Git objects remain in repository history.

The decoded aurora cache holds up to 400 grids, enough for a five-minute day. A verified latest NOAA grid is also retained during the browser session with its actual observation and forecast timestamps. Explore chooses the saved forecast target closest to the selected instant, excluding measurements later than that instant. It carries the most suitable recorded grid through capture gaps without the live ninety-minute expiration rule. The actual grid and both original timestamps remain unchanged. It labels both the actual forecast target and its input observation time. It does not change saved probabilities, reuse the current grid for arbitrary dates, or invent history before recording began. The rendered emission crossfades the eligible held selections over ten minutes of replay time, with a smoothstep weight and no contribution from future measurements. Overlapping updates remain continuous. Pin values and source clocks use the actual closest recorded forecast. Only the proportional display emission is blended; no interpolated forecast is reported. While a replacement loads, it keeps the closest cached recorded grid whose measurements precede the selected instant. Replay preparation includes the grid needed at each window endpoint even if a capture gap places its forecast outside the ordinary preload range. Times before the first saved measurements remain unavailable. Native gzip decompression is required for replay; if it is unavailable the rest of the globe continues.

The percentage is NOAA's modeled probability overhead, not a personal chance of seeing it through clouds or city lights. A forecast is also different from a confirmed sighting. NOAA says bright aurora can sometimes be visible roughly 600 miles from its overhead location. Pins separately report distance to nearby cells above 10 percent, with daylight/twilight qualifiers. Clear dark skies, an unobstructed horizon and low light pollution matter; Moonlight can reduce apparent brightness. There is no local cloud fraction or guaranteed naked-eye visibility calculation. The authentic storm fixture has Kp 5.67; no storm grade is inferred by rounding it.

## Astronomy and clocks

[Math notes](DAYLIGHT_GLOBE_MATH.md) document the NOAA Meeus Sun calculation, minus 0.833 degree sunrise horizon, polar transitions, Schlyter lunar orbit with perturbations and independent reference fixtures. The Sun disk follows the same calculated direction that lights Earth, with a fixed approximate 0.535-degree angular diameter. It is placed 75 display units from the current camera along that direction, avoiding the large false parallax of a compressed Earth-centered distance. True observer parallax, annual solar disk variation and relativistic corrections are omitted. The internal solar-framing test helper sits 145 degrees from the Sun at radius 4; an approximately 10.395-degree aim shift and at least a 58-degree horizontal field fit Earth and Sun together. A 42-degree vertical floor preserves Earth's limbs in ultrawide and short landscape views. Orbiting uses Earth-centered framing; the actual Sun is visible when its bearing enters the camera view.

The photosphere uses a simple linear limb-darkening law with coefficient 0.6. The halo and restrained rays illustrate camera bloom, not measured solar corona or a calibrated exposure. `js/globe-optics.js` computes camera-relative spherical disks for Earth and the displayed Moon. Single-body visible area uses analytic spherical-cap overlap. Visible photospheric flux integrates continuous angular arc unions, weighted by the same limb-darkening law. Overlapping Earth/Moon shadows cannot remove the same light twice. Core pixels use actual GPU depth testing. The displayed Moon is opaque from either side. Zero visible solar area also hides the core explicitly, so a near-plane slice through the compressed Moon cannot reveal a contradictory Sun. Observer bloom may spread a small glint over a foreground limb, but its strength follows remaining flux and reaches exactly zero at full occultation. Compression makes these visual crossings unsuitable for predicting terrestrial eclipse locations or dates.

The sky is centered on the camera at radius 120 to represent infinity, while Earth-oriented directions follow the selected instant. Measured magnitude controls size and brightness with a quarter-power display compression; it does not represent a single photographic exposure. B-V gives approximate stellar colour. The 23 missing indices use a neutral colour. Local solar glare dims nearby stars. Failed catalog loading leaves no invented fallback stars and is disclosed in the accessible summary. Keeping stars visible beside bright Earth and Sun expands the display dynamic range, as explained by [NASA's exposure discussion](https://science.nasa.gov/blogs/earth-matters/2011/09/28/where-are-the-stars/).

Current Earth uses date-specific obliquity. Lunar direction follows the selected instant. Earth and Moon share the same world-space Sun direction. Orbital distance is compressed, so the visible lunar phase depends on the virtual observer's position and can differ from the phase seen from Earth. Orbiting never rotates the light away from the Sun. Surface libration is omitted. The Moon uses a normalized Lommel-Seeliger disk law, following the lunar scattering function described in [USGS's lunar photometry notes](https://isis.astrogeology.usgs.gov/8.2.0/Application/presentation/Tabbed/lrowacpho/lrowacpho.html). The former Lambert sphere made the October 9 thin crescent nearly black. Lighting now operates in linear space before display encoding, and the mesh resolves the thin illuminated limb with 128 by 96 segments. A small ambient term keeps the dark surface faintly visible. This is illustrated brightness with an expanded display range, not calibrated lunar radiance, a Hapke model or an Earthshine calculation.

It stops automatic orbiting and leaves the selected instant, Live mode, pin and calculated lunar position intact. Dragging and zooming remain available. The control sits beside fullscreen, stays disabled during preparation and is hidden if WebGL is unavailable.
